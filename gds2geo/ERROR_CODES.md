# GDS2GEO V1.1 模块退出码

本交付包的四个主阶段使用文本 stdout/stderr，manifest 的 `errorContract.type` 为 `none`。
task_layer 将非零退出统一报告为 `QS-TL-MOD-EXEC`，并保留实际 exitCode 和完整诊断。
本模块没有自行定义或伪造 QS 错误细分码。

| 退出码 | 适用阶段及触发条件 | 可恢复性 | 处置 |
| --- | --- | --- | --- |
| 0 | 阶段成功；`--help`、`--version` 正常返回 | 无需恢复 | 平台核查本阶段产物后继续；全链必须四阶段均成功 |
| 2 | 四阶段：参数/路径错误、运行目录不可用、输入缺失、CSV 拒绝、源/目标包加载或初检失败 | 修正后可重跑 | 检查固定输入、全部显式绝对路径、CSV 内容、日志及完整配套 JSON；必要时重建上游 |
| 5 | 四阶段：几何/材料/接触约束拒绝、互斥量忙或 abandoned、Gmsh 缺失/版本不符/失败/超时、网格验收、文件写入或事务发布失败 | 取决于原因；旧的有效阶段产物保留 | 阅读 stderr 和本阶段日志；等待占用者结束，或修正输入、权限、资源及环境后重跑；保留随包 gmsh.exe 4.11.1 |
| 6 | source：CLI 顶层捕获的未分类标准异常/内部错误 | 通常需开发排查 | 保留输入、四 EXE 版本及全部日志；报告完整原始错误，避免重复强行重试 |

`5` 不等同于某一种系统 IO 错误，也不单独代表超时。请结合实际诊断判断。
Windows 在程序入口前拒绝启动、用户终止或操作系统异常终止产生的状态码不属于模块业务退出码。

本包不附带 `run_all.ps1`。README 的 PowerShell 参考逐阶段透传主程序非零退出码；
参考代码自己的产物/同代检查使用 PowerShell 异常，不属于上述 EXE 业务退出码。
平台用进程 API 调用时须自行检查退出码、产物与 publisher 结果，并保存完整诊断。

运行日志在 `<dataRoot>/Result/logs/gds2geo/`：`gds2geo.log`、`geo_prepare.log`、
`geo2em.log`、`geo2thermal.log`。各程序日志覆盖其上次调用，平台应另行保留每任务 stdout/stderr。
导入诊断和私有暂存使用同一运行根。Windows 命名互斥量保护并发，不创建 `.lock` 文件。

每个阶段只负责自身文件组的事务发布。后续阶段失败时，已成功的上游可能已更新，
下游保留的旧结果不表示本轮成功；应修正原因并重跑完整四步。全链不是跨四目录的单个原子事务。
Model/Setting 下正式件由 task_layer publisher 管理；publisher 失败使用平台的 `QS-TL-IO-ERROR`，
不改写模块原始退出码。平台仅在全部必需阶段成功后把整个建模任务标为成功。
