# GDS2GEO V1.2 退出码与恢复

调用方应记录可执行文件名、参数、进程退出状态、实际退出码以及完整的 stdout 和 stderr。一次 both 调用同时处理两套结果。只在进程正常退出并返回 0 后读取本次请求的全部正式文件。

| 退出码 | `gds2geo.exe` | `geo2msh.exe` | 调用方处置 |
| --- | --- | --- | --- |
| 0 | 所选目标的几何包已发布，或帮助、版本查询成功 | 所选目标的网格包已发布，或帮助、版本查询成功 | 几何目录核对 GEO、同主名 JSON 和 MATDB。网格目录核对 MSH 和本目标 MATDB。both 要核对两个目录 |
| 2 | 参数不合法、输入缺失、GDS 或工艺初检失败。例如直出几何时误传 `--runtime-dir` | 参数、路径或输入包初检失败。例如请求 em 却传入热几何，或 GEO 与同主名 JSON 的记录不符 | 按诊断修正路径和参数，核对目标及输入文件。受损几何包从原始输入重新生成，再将该包三件一同交给网格程序 |
| 5 | 几何生成或目标准备失败、材料或层接触关系不满足要求、目录互斥冲突、事务发布失败 | Gmsh 缺失、版本不合、超时或失败，网格与材料验收失败，互斥冲突或发布失败。热实体导出自身的业务失败也返回 5 | 按最先出现的具体诊断排查几何、工艺、路径权限或资源。核对外置 Gmsh 为 4.11.1。若诊断为互斥占用，待占用者退出后重试 |
| 6 | CLI 捕获未分类的标准异常，诊断含 `internal error` | `export-thermal-entities` 子命令捕获未分类的标准异常；常规目标网格生成失败归入 5 | 保存输入、两份 EXE 的版本与 SHA-256、参数和完整诊断，交由维护方复现 |

几何直出使用系统临时目录，诊断来自进程文本输出。网格调用可用 `--runtime-dir` 将日志和暂存指向可写的 `Result/logs/gds2geo/`。同名程序日志会被后续调用更新，调用方应逐次留存。程序通过同机系统命名互斥保护共享目录。

重跑时请保留诊断指出的备份和已有结果。若输出目录已有旧版网格回执或只有部分正式件，改用空目录重跑。后续网格失败时，先前已成功生成的几何包可供重试。已有网格的存在本身不足以确认本次运行成功。

Windows 启动失败或异常终止应另外记录操作系统错误和退出状态。两个程序提供文本诊断，平台侧 QS 错误码的归类由调用方处理。

## 平台 QS 归一

本包 `errorContract.type` 为 `none`，程序输出文本诊断，不直接发出 QS JSON。按 doc1.5，平台将外部进程的非零退出码归一为 `QS-TL-MOD-EXEC` 并保留原 exitCode；上表的 2、5、6 分别给出触发条件、可恢复性和处置。启动失败、异常终止及 publisher 失败由平台各自登记，不将其误记为本模块成功。
