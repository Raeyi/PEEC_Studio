## model.peec V1 二进制布局

文件不压缩。所有整数 little-endian；矩阵为 IEEE-754 float64、逐行排列，保存完整矩阵，不强制对称化、不降精度、不稀疏化。

固定头部 88 字节：

| 字节偏移 | 类型 | 含义 |
| --- | --- | --- |
| 0 | 8 bytes | ASCII `PEECPK01` |
| 8 | uint32 | 版本，1 |
| 12 | uint32 | 字节序标识，0x01020304 |
| 16 | uint64 | P 节点数 N |
| 24 | uint64 | L 支路数 B |
| 32 | uint64 | 端口数 K |
| 40 | uint64 | 元数据字节数 M，最多 1 MiB |
| 48,56,64,72,80 | 5×uint64 | L、P、B2N、PORT、元数据的绝对文件偏移 |

载荷按以下顺序连续存放：

1. L：B×B 个 float64。
2. P：N×N 个 float64。
3. B2N：B 行，每行两个 int32，0-based，地节点为 -1。
4. PORT：K 条，每条两个 int32 端点与一个 float64 参考阻抗，共 16 字节；顺序与输入 port_em.json 一致。
5. M 字节 UTF-8 元数据：SI 单位、坐标框架、输入 DIM 和 PEC 假设标识。

N、B、K 必须为正且不超过 `2^31-1`；各块按上述顺序连续存放，偏移须与尺寸推导值一致。文件总长度必须精确等于元数据偏移加 M，不允许截断或尾随数据，尺寸运算不得溢出。

读取前检查版本、溢出、分块偏移、文件精确长度，再检查矩阵有限数、拓扑和端口范围。整体SHA-256与输入来源由阶段artifacts.json内部工件索引校验。新CLI要求索引存在且与当前数据匹配；stage_receipt.json仅作可选自证，不作为消费门槛。包头与矩阵二进制布局不变。

写包直接使用现有矩阵行，不先写散文件，不拼接包大小的内存缓冲。通过同盘唯一 `.partial` 关闭并核对长度后发布；签发阶段仍读回文件计算指纹。这是单个模型文件的发布，不能描述为整套提取/求解结果的跨文件原子事务。

旧 Solver 和部分外部工具仍依赖原散文件。使用 `--matrix-format bin|txt|both` 显式导出；不能将新包直接交给旧读取器。

## Post_Source.txt V2

`PEEC_POST_SOURCE_V2` 依次保存以下字段和数据段；复数每行两个有限数 `real imag`：

```text
PEEC_POST_SOURCE_V2
FREQUENCY <Hz>
PORT <1-based excitation port>
CURRENTS <B>
<real imag, B rows>
VOLTAGES <N>
<real imag, N rows>
CHARGES <N>
<real imag, N rows>
```

电流单位 A、电压 V、电荷 C。节点/支路顺序与同次模型一致；CHARGES 包括端口注入的贡献，按原始势系数矩阵定义满足 Pq=V。辅助零电荷节点保存0。Qe 后处理使用 Q/面面积，不用支路电流散度冒充电荷。空间 E 场直接使用 Q；不再在后处理中从缺少端口电流的物理支路集合重建它。

可选段为 MAGNETIC_CURRENTS、MAGNETIC_VOLTAGES、MAGNETIC_CHARGES，各最多出现一次，长度分别与电流、电压、电荷段相同。本版 Solver 无磁激励，省略这些段时为0；外部提供非零磁电流时必须同时提供明确的磁电荷。未知、重复、不完整段及非有限值拒绝。

V2 电荷段为必需。旧 V1 源文件需要通过本版 Solver 的 `--export post` 重新生成，不能隐式补为0或按错误的电流散度继续画图。模型包 V1、Post_Model V1 和 PEEC_STAGE_V1 的格式保持不变。发布前，后处理还会检查计算生成的所有场分量和图幅值；发生非有限数时不替换已有图。
