# v1.2 重发版清单（2026-11-02，平台 → 各模块团队）

背景：DATA_LAYOUT v1.1 → **v1.2**：
① 输入文件名 `port_em.json` → **`source_em.json`**、`port_thermal.json` → **`source_thermal.json`**；
新增预留件 `boundary_em.json` / `boundary_thermal.json`（UI 输入，暂无消费方、格式待定）；
② 模块包**只含四件套**（exe / README / ERROR_CODES / manifest），不再携带 `examples/`、`templates/`；
③ 自测案例改为**包外案例包**单独交付（必做，格式见下）。

## 五、案例包通用规范（三模块一致）

- 目录命名 `<module>_cases_YYYYMMDD/`（或同名 zip），**与模块包分开交付**——放进模块包会被打回；
- 每个案例 = 完整 dataRoot 布局：`Model/` + `Setting/`，输入件齐全（source_*.json、set.json、网格），不引用外部资源；
- 每案例一份 README：输入怎么来的、**预期输出/验收点**（关键产物、字段、数值参考）、已知局限；
- 平台方归档 `dev/cases/<module>/`，用于 dev_case 回归与联调自测。

## 六、过渡期说明（平台侧行为）

- 旧版交付**继续可用**：task_layer 预检/静态校验同时接受新旧名（新名优先）；
- requiredInputs 检查以模块 manifest 声明为准：compact_em 重发版（manifest 声明
  `source_em.json`）落地前，UI 继续写 `port_em.json`；重发版部署后 UI 切换为
  `source_em.json`，平台侧零改动；
- 当前 compact_em 包自带 examples/，平台注册期会打一条警告（过渡期行为，重发版后消除）。
